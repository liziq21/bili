# 产品边界：只读客户端

状态：生效（2026-11-10）

本文件是「哪些功能在这个 app 里根本不做」的唯一事实源。`app/AGENTS.md` 的
「可扩展数据源与本地个性化」段、`.jules/issue-triage-prompt.md` 的审核判据，以及
Linear 工单的取舍，都引用这里，不各自重写一遍。

## 1. 只读，不登录

- app 不实现账号体系：没有登录页、没有凭据存储、没有凭据注入。
  仓库内不保存 Cookie、SESSDATA、access_key 或任何账号级凭据（见
  [`packages/AGENTS.md`](../packages/AGENTS.md) 的 fixture 规则）。
- 所有远端端点都是匿名可访问的。任何「需要先登录才能工作」的设计在本项目里不成立。
- 由此推论：**一切写往平台的写操作都不做**，包括但不限于发评论、回复评论、发弹幕、
  投币、点赞、平台侧收藏、平台侧订阅、平台侧播放列表编辑。这不是「暂缓」，也不是
  「等登录体系就绪再做」——登录体系本身不在路线图上。

## 2. 本地个性化是唯一允许的写操作

订阅、收藏、观看历史、本地播放列表、播放进度、设置项等个性化能力**只写本地**
（Drift SQLite / SharedPreferences）。它们不承诺与平台账号同步，也不承诺跨设备同步。

现状说明（2026-11-10 核查）：视频详情页的点赞 / 收藏 / 关注按钮仍存在，远端能力
接口缺席时会走「乐观更新 → 失败回滚」或回退到本地存储。这是既有接缝，不是新增功能
的方向指引；新功能不得以它们为模板添加写往平台的行为。

## 3. 已有能力的数据只读使用

需要平台数据的只读能力（评论列表、二级回复分页、弹幕渲染、动态 Feed、远端播放列表
内容、直播信息与流地址）都在范围内。它们与第 1 节的边界不冲突：读不需要登录态。

## 4. 对工单与排期的约束

- 一张工单只要有一项交付物落在第 1 节的写操作里，就**不得**作为可执行工单排期；
  应缩到只读部分，或直接关闭。
- triage 的结论档位里，`confirmed-actionable` 不覆盖第 1 节；遇到越界项要显式指出并
  引用本文件，而不是只写一句「暂不支持登录态」。
- 工单标题和描述可能由模板或父单机械复述而来，**不构成对产品边界的扩大授权**。
  描述与本节冲突时以本节为准。
